# Agent work and artwork arrival

The preview.20 effects are independent vanilla JavaScript in `runtime/presence.js` and `runtime/agent-motion.js`. They reuse the existing anonymous presence room. They add no document fields, remote service, runtime dependency, viewport movement, selection changes or save delay.

An agent with a factual nonempty activity status gets a quiet roster accent. A known Page/layer/rectangle gets a working outline and label; no location means no canvas marker. Activity completion/error and explicit clear remove the work area; expiry, disconnect and shutdown remove stale indicators. Participant dragging and keyboard placement retain their existing controls.

Only artwork committed by a known agent is eligible for arrival effects. The server keeps a 15-second chronological receipt ring (16 per Paper, 64 Papers), including null-actor barriers for human/unknown saves. It records the successful optimistic base revision, result revision and anonymous actor. A renderer checks the actual fetched revision against an exact transition or a contiguous suffix by the same agent. A gap, mixed writers, newer unproved fetch, replay, expired receipt, initial/forced load or absent capability gives an ordinary update. Feedback, guides, asset upload alone and failed saves have no artwork receipt. Attached owner MCP completion carries base/result to the existing loopback presence route; a superseded completion is conservatively omitted. A watcher event without a proved base replaces prior proof with an unknown-write barrier; a late completion cannot relabel replayed bytes. A delayed document or poll snapshot cannot replace newer live completion/departure state. Legacy owner hosts get an explicit activity/location clear rather than their old resume-style restore.

Attached owner operations carry an opaque write generation captured at that individual tool call’s start. Every observed artwork write invalidates it; completion must still match both generation and current revision. These generations do not expire with display receipts, are bounded to 64 Papers, and eviction/restart gives a fresh random generation. Concurrent tool calls keep their own nonserialized operation token. Hosts without `features.agentCompletion:1` receive ordinary updates without inferred agent proof.

At most eight visible changed layers receive identity-labelled outlines for 1.8 seconds. Added layers receive a 360ms opacity reveal, preserving their model opacity; updated layers get only a dashed settling marker. Added ancestors suppress duplicate descendant effects, and child-list-only changes do not highlight existing containers. Effects replace previous effects on rapid commits and disappear on page/scene changes, hiding, reduced-motion preference changes, disconnect and disposal. Reduced motion uses no artwork animation and a 900ms static marker. The existing presence heartbeat/expiry timers remain; no synthetic animation-frame loop is added.

The reveal uses Web Animations on live DOM elements, changing opacity only. It never writes inline artwork style, geometry or positioning transforms. JSON/bundle output uses saved model data; browser HTML/PNG/preview export clones the artwork subtree, outside the presence overlay. DOM cloning does not copy Web Animations. Home/server previews render the model. Thus neither overlay chrome nor reveal animation belongs to an export.

## Reproducible local review

From the source checkout, run `node tests/fixtures/agent-motion.mjs`. Open the printed loopback URL. The fixture creates a disposable library and local edit invitation, then uses actual shared MCP `paper_activity` and revision-checked `paper_save` calls. No account, live Notion, installed plugin or tunnel is used. Enter commands in its terminal:

1. `work` targets the existing layer; `area` targets a real rectangle; `page` targets the known Page. `unknown` leaves only a roster status. `clear` clears activity.
2. `work`, then `spawn` creates a real card with nested text/accent layers. The highest new parent reveals once, with a brief added marker. `update` changes the existing object and shows an updated marker. `burst` commits three consecutive same-agent additions without sleeps.
3. `human` changes the existing object under a human client; `fail` attempts a stale save. Neither gets agent commit effects. Open a second window before an edit to check live refresh. Reload after the edit to check initial-open suppression.
4. While working/settling, pan, zoom, change Page, hide the tab, toggle reduced motion, drag the participants strip and use its arrow keys/Home. Effects must neither intercept artwork input nor alter camera, model, selection or undo.
5. Capture/export immediately during a reveal: HTML/PNG/Paper preview must contain full model opacity and no presence chrome. In browser devtools, `original.cloneNode(true).getAnimations({subtree:true})` is empty even while the original is revealing. Inspect the model/API response for unchanged geometry and no motion fields.
6. `quit` stops listeners and deletes the fixture. Run again with `node tests/fixtures/agent-motion.mjs --poll` for the scoped polling path used by native/Internet views. The fixture’s loopback forwarding listener only sets `poll:true` on access; saves and receipts use the same server/MCP paths.

Focused checks: `node --test tests/agent-motion*.mjs tests/agent-presence.test.mjs`. Build with `npm run build:ui`; the native bundle includes the same presence code. Full tests package committed HEAD, so commit first, then `npm test` and `npm run verify:assets` on a clean tree. Desktop/native visual acceptance is a separate review from these automated contracts.
