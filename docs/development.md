# Development working ground

## Sources

README.md owns usage and sharing; DESIGN.md owns product/editor behavior and design
boundaries; docs/releases.md and CI own source/package/native acceptance distinctions.
GitHub issues and pull requests remain the product work records. Delivery evidence
belongs to the revision and environments it was gathered on.

Private operator/installation context, if provided, is stored outside the tracked
product tree at t3-development/continuation.md under `git rev-parse --git-common-dir`.
It is optional and grants no access or new work.

## Selected methods

Notion is the live editable source of the selected Core methods and of Software
methods such as agentic-new-feature. AGENTS.md owns their catalog route and loading
instructions. No provider profile supplies project skills or personal synced skills,
and this repository holds no copies of the methods. Each new task reads the live
catalog and the relevant method and records the version actually consumed; a task
cache is disposable. Project knowledge and capable native reasoning supply software
expertise; extra domain methods are selected when useful.

## Execution and proof

Linux is suitable for source tests, deterministic builds and browser-side work.
Mac-specific plugin and host behavior needs a separately qualified Mac test route.
Personal Papers, installed plugins and active invitations are not part of a source
checkout and are not moved with it.

### Evidence for visible changes

Exercise the real affected flow with synthetic Papers and isolated storage. The entry
points are listed in [AGENTS.md](../AGENTS.md#verification-and-delivery). When
screenshots help, capture the baseline and the changed state with the same data, theme,
zoom and window size. Use a short browser clip when timing, motion or interaction
matter. State what was exercised, on which revision and browser or host, and what was
not. The T3 preview browser can be used where it is available. When the PR is linked
and watched in T3, GitHub feedback on it reaches the chat carrying the change. CI,
source tests and native product proof are reported separately.

The owner selects the model and effort for a task or delegates that choice. Provider
login and model listings do not prove a useful task; access is proven by the task it
actually supports. Source checks and native UI/access proof are recorded separately.
Independent work starts from current main, which carries this bootstrap; a continuation reuses its task's workspace.
