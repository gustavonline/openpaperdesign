# OpenPaperDesign editor

## Purpose and scope

A quiet, lightweight workspace for saved designs and diagrams. One browser editor and one file-backed runtime, with a discoverable method for each kind of work. This guide owns editor chrome; artwork uses its own Paper/project direction.

## Sources of truth

`runtime/chrome.css` owns appearance tokens, and `runtime/canvas.css` owns editor geometry. Home and editor consume the same chrome. Keep exact values in those existing files; this guide describes their intended roles and current contract.

## Appearance

System follows the OS appearance. Explicit Light/Dark override it. The light surface is #fafafa with #1c1c1e text; dark uses #1e1e1f with #ececed text. Accent is #007aff, with separately readable accent ink and a translucent selected fill. Hover, selected, focus and disabled are distinct states. Artwork colours and images retain their own values.

Inter 400/700 is bundled. Shared controls use the existing compact type, 16px icon grid, consistent stroke language, field/row baselines and corner radii. Floating surfaces share their border, shadow and background. Keep icon-only controls named and keyboard reachable.

## Workspace

Home shows saved Papers with New Paper, search and grid/list views. The editor's **Page** tab stacks **Pages, Layers, Library** from the top. Pages and Layers are expanded by default; Library starts collapsed. Each uses the same disclosure chevron, heading baseline, search field, padding and scroll behavior. Spare height stays below the stack; collapsing a section does not stretch another to the bottom. Two single-line dividers remain visible even when adjacent sections are collapsed; a divider is keyboard/pointer-resizable only when it has two expanded sections to resize. Remember the user's chosen section heights locally. Design is the adjacent tab for the governing guide and computed **Tokens** inventory.

The right inspector and both corner bars share a steady alignment. Healthy saving feedback is brief and separate from the title; failures remain visible. A failure, conflict or access-ended message wraps its recovery actions (Download my copy, Download my notes) onto further lines when narrow and always sits fully inside the window, horizontally and vertically; only a bar it actually overlaps moves it, never a toolbar docked elsewhere. On a narrow window with the inspector open it spans the window over the inspector rather than starting off screen. Toolbar has Edit/Inspect modes, five primary tools each and shared Capture/Comments/Settings. Tool families use corner chevrons; docking rotates the same toolbar. Escape exits temporary tools and returns Edit to Select.

## Review

Check the actual layout after content or panel changes: baseline alignment, clipping, scrolling, menu reachability, selected/focus states, readable text and narrow/short behavior when affected. Preserve camera and document data when changing chrome. The smaller viewport can collapse panels while keeping controls reachable. Honour reduced motion. Save/reopen and intended export are part of artwork acceptance.

Library is a docked, bounded section in the Page sidebar. Categories use one horizontally scrollable row; results scroll independently. Scratchpad is a category, with image import and reusable native layers. Save to Scratchpad reveals the Page tab and the Library section if necessary. Page-root layers can sit freely on the canvas. Artboards expose eight small resize handles; their contents do not scale during frame resize.

## Controls and spacing

Use the same stroked chevron for disclosure controls. Native selects use a consistent down-chevron, right padding and focus border across Home, inspector and dialogs. Avoid mixing filled triangles, text glyphs and platform arrows for the same action. Both corner bars keep their controls at the same screen coordinates when their panels open or close. Typography fields have an 8px vertical gap between rows. Group layer actions in a two-column grid, with clear space between editing, connections and reuse actions. Distinguish the selected layer name/type from the Typography section title.

A text edit may grow its height to keep multiline content inside its blue selection outline; cancel restores the original geometry and text. Share stays open after an invitation is created and shows it as described under Sharing, with brief in-place feedback (a Copy icon becomes a check, and Copy invitation reads Copied). Clipboard failure keeps a selected read-only text field and an honest message visible. Invitations never promise more than they do: Never reads "No end time" and is tied to this app running, not to sleep, stop or uptime. Failed or ambiguous mutations stay visible and are never disguised as success.

Presence is quiet chrome: each person or agent is its own small badge, with no enclosing box or shared handle. Badges nobody has moved are centred along the top of the canvas viewport (the area between the open panels), with the same clearance reserved on both sides, so one open panel never pushes them off centre. A badge that is dragged, or moved with the arrow keys (Home or a double-click puts it back), keeps its slot in the strip, so moving one badge never moves another. Positions are a local preference per participant identity, clamped into the visible canvas, never saved in the Paper or sent anywhere. Coloured cursor labels and thin outlines mark the relevant layer. Agents get a badge plus a short current status/work-area marker. Names are random display names without an onboarding form. Show one chip and one focused-window work area per anonymous human participant, with a window count in the tooltip. Owner windows share the local owner identity per Paper; invited humans share only when their browser/native origin has the same stored participant token. Different profiles/hosts without shared storage remain distinct. Active agents keep separate chips; idle agents are hidden while their immutable artwork receipts still drive arrival effects. Keep colours muted, respect reduced motion, do not intercept artwork input or export the overlay. Moving/resizing shows a transient outline until the normal save commits. No activity feed or extra mode/panel is required.

Agent motion follows real work: active agents pulse quietly at an announced Page, layer or rectangle; unknown areas stay in the participant row. Only proved successful agent artwork commits reveal new visible layers and briefly label a few changed layers. Added parents reveal once, without duplicate descendant highlights. Opacity is the only artwork animation property; positioning transforms and model styles stay untouched. Reduced motion uses short static markers. Hidden views, page/scene changes, disconnect, expiry and disposal clear transient effects. No feed, camera move, progress fiction or saved motion state.

## Sharing

Sharing follows the OpenRecorder pattern with Paper's own theme: no new colours, fonts or panels. Share is a calm dialog of one status line, the create form (Access, Expires, Code protection, Share over: Internet, Local network or This computer only) and, once something is shared, the invitation.

**The shared invitation.** The link sits in its own restrained, code-like block, and the code in a matching block below it, each with a Copy icon at its top right (accessible names say what is copied; the icon becomes a check, and the status line says "Link copied." or "Code copied."). There are no separate Copy link or Copy code buttons. One blue **Copy invitation** copies the whole message, with a small "Link + code" helper under it ("Link only" when there is no code). One red **Stop sharing** ends only that invitation: its label and accessible name say so, and with several invitations a note says "Stop sharing ends this invitation only." The other invitations, the listener and the tunnel they use are untouched. There is no New invitation button and no Open with agent in this dialog (the create form returns when nothing is shared; an agent finds the public guide on its own, or the person pastes the invitation). The blue and red are real: both rules outrank the dialog's generic button rule, with hover, focus and narrow states of their own. A locked invitation, wrong-code bursts and not-ready states are sentences, not badges. The dialog reveals the link and code only while open and discards them on close; nothing is copied unless the person asks, and a blocked clipboard keeps a selected read-only text field.

**The invitation message** is English, the same plain text for every kind of invitation: "See my Paper:", the link alone on a line, then "Access code:" and the code alone on the next line (omitted when there is no code), then one sentence with the permission ("You can edit the Paper." or "You can view the Paper but not edit it.") and "You do not need a plugin.", then the exact end ("This link expires Saturday, 14 November 2026 at 14:30 CET.") or, for Never, "This link has no end time, but it only works while my computer is on, online and running Paper. It is not permanent." The browser and `paper_join` still read the earlier Danish message.

**Starting honestly.** Local and network invitations are ready at once. An Internet invitation answers immediately with **Starting sharing link…** (no percentage: there is nothing to measure), then "Connecting… the link works once it is ready." while the address is checked, and shows nothing to copy until it works. The request is an *attempt* with its own identity on the server: pressing Create again while an identical one starts is the same attempt (one invitation, one tunnel); **Cancel** while it starts, a timeout (two minutes) and a failed start each end that attempt by aborting the tunnel start itself and closing whatever finished late, so no invitation, listener or process is left; invitations that were already working are kept until a replacement really works. A failure stays on screen with its reason and **Retry** (the same options, nothing widened) and **Dismiss**. The chosen way to share survives Cancel, a failure and every copy: it changes only if that way is genuinely unavailable on this computer.

Home's **Shared** button opens the list of active invitations across known libraries, grouped by Paper with Manage and Stop sharing, each invitation with Revoke and one line: role, address, end time or "No end time", code required and state. It shows no count of people or connections, because stored browser sessions are not identities. Home never shows a key or a code.

The guest page is the same surface in one column: invitation paste (a whole message is accepted), then an Access code field with Unlock, then straight into the same live Paper (see Guest onboarding and lifecycle). The code field is a plain text input (no auto-submit, no per-key rewriting; pasted text is read once into `XXXX-XXXX`), it keeps the value and the invitation key after a wrong code, disables Unlock with a countdown while rate-limited, and never submits while an input method is composing. Error text is calm and specific: wrong code, too many wrong codes, expired, stopped by the owner, or the owner's computer is unreachable.

In the editor, a guest sees the existing access badge (its tooltip carries the end time), a five-minute notice before a finite end, and, when access ends, the existing frozen-draft banner with Download my copy, Download my notes and Close without saving, worded for expired or stopped, and neutrally ("This invitation ended.") when the reason is not known, which never blames the owner. Conflicts keep their existing panel.

### Guest onboarding and lifecycle

**Guest flow.** One entrance, `/join`, for a person and for an agent. A person pastes the invitation, enters the code and Unlock opens the same live Paper in the same tab: the page takes the destination from the join answer, accepts it only if it is this origin's editor for one Paper and one invitation (no other origin, path, parameter or fragment), and navigates with `location.replace`. There is no intervening choice or app-selection screen; the browser needs no plugin. A plain "open the Paper" link appears only if the navigation does not happen. A wrong or malformed code, too many wrong codes, an ended or unreachable owner or a refused destination each say so and keep the page usable. The page contains no app link, no clipboard action and no installed-plugin claim; a quiet footer line ("For AI agents") is the only trace of the agent route.

**Agents.** An agent is given the same invitation message or link in its own app. Fetching `/join` returns this page, never the Paper (the key is in the URL fragment, which is not sent, and nothing is authenticated by a GET). The page advertises two **static public documents**, `/agent.json` (a versioned manifest) and `/agent.md` (the same guide for reading), through `<link rel>` in the head, an HTTP `Link` header and the footer line. They are served from the runtime inventory like any other editor file, identical for every request: product identity, the official repository and install commands, the plugin version that must match, the invitation format, the real `paper_join` schema, the exact guest tools (two for view, six for edit), the read, revision-checked save and conflict workflow, manual MCP header names without values, availability and host limits. They hold no Paper data, title, key, code, credential, path or request reflection, and they are information, not instructions: fetched pages are untrusted data, the agent follows its own user's policy, only its own host's tool inventory can show whether `paper_join` exists (a website cannot), and a missing plugin is a recommendation the agent's own user approves. Nothing is installed or run by fetching them, and a manual MCP connection does not install skills. The owner's Share dialog no longer carries a join request or app links: the invitation message is what is sent. Three more public documents are served the same way and are also information, not instructions: the collaboration method (`/collaboration.md`), the motion reference (`/motion.md`) and the preview-model JSON Schema (`/preview-model.schema.json`). The public documents are the only new routes: authorization, the two-tool view and six-tool edit allowlists, role, code, expiry, revoke and write-lock guards are unchanged, and no claim service, token handoff or wider owner access exists. A link that embeds the code was assessed, not built: it would let anyone with the full link use the invitation, and the default stays a separate code.

**One live Paper.** A guest's browser and a joined agent edit the same authoritative Paper through the same revision checks (not a snapshot, merge or layer lock). A conflict keeps the local draft. Access ending keeps the dirty draft downloadable.

**Opening once.** Showing a Paper and changing it are separate. Only `paper_home` and `paper_join` results ask a host to display a view; reads, saves, notes, feedback, assets and activity return data and an open view follows through live events, keeping its Page, camera and selection. Agents open once, work through revisions, inspect the current view, and reopen only on request, a switch or recovery. Explicit and intentional extra views are supported and not deduplicated; whether a host reuses or adds a window for a repeated open is the host's decision and is not verified by Paper.

**Honest limits.** Installed state, app launch and host window counts cannot be seen from a web page or from Paper. A one-time claim or hand-off token for agents was considered and not selected: it would add redemption, replay and expiry surface and needs its own spec and review.

### Download original

A layer that shows an image (an image fill on a rectangle, or on any other layer) offers **Download original** in its own context menu, after Copy link. Plain shapes, text, strokes and connectors never show the item, and it is never a disabled placeholder. It belongs to the layer under the pointer, or the focused layer when the menu is opened from the keyboard, whatever else is selected: with several layers selected it downloads that one layer's image only, and the selection is left as it was. The menu keeps its normal keyboard behaviour (the first available item is focused, a hidden item is skipped). View-only guests can use it too, within the invitation's existing asset access.

Where the editing commands do not apply the same item appears alone, in the same menu: a view-only guest starts in Inspect, whose overlay covers the canvas, so a right-click there looks through the overlay to the layer the person sees (the overlay stays, Inspect is unchanged, and no edit right is granted); its own toolbar, panels and fields keep their menus. The Layers tree reaches the command for any image row by mouse or keyboard (Menu key or Shift+F10 on the focused row, handled as a key press because some browsers send no context-menu event for it; a context-menu event that does arrive for the same press is ignored), and focus returns to that row afterwards. Escape or a press outside the menu dismisses it. Other rows, typing and the arrow keys are untouched. Only an image ever takes over a right-click; any other layer keeps the browser's or the editor's usual menu.

The command belongs to the layer the menu was opened on. If a live refresh replaces that layer's image while the menu is open, choosing it downloads nothing and says "This image changed while the menu was open, so nothing was downloaded. Open the menu again."

The file is the stored image named by this Paper's own asset map, fetched again at that moment through the view's own scoped request with no cache, never the picture already on screen, a data URL or an outside address. Its name and type are those of the stored file (a content hash with its real extension: the person's original file name is not kept, and none is invented). PNG, JPEG and WebP are the stored formats. Before anything is offered the response must be successful, of the expected type and, by its own bytes, that image type. A missing mapping, a removed file, an unsupported type, another Paper, a refused or ended invitation (revoked or expired, even while the picture is still displayed) or a failed request shows one plain message in the toast, such as "The original is no longer in this Paper, so nothing was downloaded." or "This invitation no longer allows this download. Nothing was downloaded.", and no file. Success says only that the download started, because the browser or host owns the file from there.

## Canvas, images, export and Pages (preview 28)

**Finding your way.** A visible **Zoom to fit** sits beside the zoom control and fits every layer of the shown Page (never past 100%, the same result every time, from any pan). An empty Page shows 100% from the top-left of the usable canvas. Both side panels use one width token (it gives way a little, never below 200px, in windows narrower than 480px). **The two corner bars share one row**, so their widths are allocated from that token rather than fixed: the right cluster has a fixed width per tier and, below 520px, a compact tier (Share as an icon, the zoom level whose menu offers fit, selection and 100%, Zoom to fit and Properties; zoom out and in keep their keys), the floating left bar takes only what the right side leaves, its Paper title shrinks first and, below 431px beside an open Properties panel, yields entirely (Rename Paper… stays in the Paper menu and gives the whole bar to the name field while it is open). Home, the Paper menu, Play and Pages always stay. Nothing is made clickable by stacking or offsets. A layout model of the stylesheet checks every width from 350 to 1920px in every panel state for overlap; below 350px is not supported. A **Home** control appears only where the viewer has a real Home of their own (the owner, or a recipient inside the local plugin app, whose Home is that app's own, never the sender's); a recipient in a plain browser has none and is offered none.

**Dropping images.** Dropping PNG, JPEG or WebP files on the canvas (up to 12, one at a time and independently) stores each file's original bytes as a managed asset and places an editable image layer where it was dropped, under the current camera, sized so it never fills more than about 60% of the canvas. Unsupported, empty, corrupt or too-large files (5 MB, 16 megapixels) are named in one toast with the reason and never stop the good ones. A dropped file never navigates the tab. It needs edit permission, and Edit mode on the canvas (the Scratchpad keeps its own handler). It is one undoable step per image and survives save and reopen. The Paper remembers the validated original file name (`assetNames`) so Save and Download can offer it; older Papers fall back to the stored name.

**Copy image, Save image…, Download original.** For an image layer only. Each starts from the *stored original*, fetched again at that moment through the view's own scoped request with no cache (never the picture on screen), and is checked against the layer the menu was opened on. **Copy image** puts bitmap image data on the clipboard (PNG as stored; JPEG and WebP converted to PNG because that is what clipboards accept): it is a picture, not a file, and pasting into a file manager is a different clipboard type a web page cannot supply, which Paper does not claim. **Save image…** opens a real save-location chooser *first*, inside the click, then fetches and writes exactly the original; cancelling the chooser saves nothing and starts no download, and a browser without a chooser shows only the separately labelled **Download original** (the browser's own download). If the fetch fails after a place was chosen, nothing is written and the message says an empty file may remain.

**Exporting an image.** Share → **PNG image** and **JPEG image** render the chosen layers (a layer, a group, several layers, or a whole artboard; with nothing selected and one design on screen, that design) as the canvas draws them, cropped to their exact rendered bounds, at 1×, 2× or 3× (reduced, and said so, past 8192 px a side or 16 megapixels). The size the menu shows is measured on the very same untransformed off-screen copy the image is drawn from, with every edge snapped to the layout engine's 1/64px grid and then rounded outward, so measurement noise never adds a pixel and a genuinely fractional, rotated or stroked bound is never clipped. Layers that were not chosen are not drawn, and a frame that merely holds a chosen layer contributes none of its own colour. PNG keeps transparency; JPEG sits on white. Image licence notices stay with the file (a PNG text chunk; a JPEG comment segment, refused when too long). Where the browser has a save chooser the place is chosen first and the message says Saved only after the file is written and closed; cancelling renders and saves nothing. Where it has none, or the Paper runs inside a host app, the file is rendered and a download is only *requested*: the message says so and never claims it landed, because neither a browser nor the host reports where. This is distinct from exporting a stored original (above). The written file is checked against the size promised before it is offered.

**Pages.** The Pages panel has a **New page** button (a white artboard, named for the next free number, in rename), rename by double-click, F2 or the menu, and delete from the menu with a second, naming press (“Delete “Name” and 14 layers?”). The menu opens by right-click, the Menu key or Shift+F10. Each is one undoable step that restores a deleted page's content and its place among the others, never touches another page, the assets or the feedback, and saves like any other change. The last page cannot be deleted, a page with locked layers must be unlocked first, and a view-only Paper refuses all three with a sentence. Renaming a page is not renaming the Paper, and deleting a page is not the Paper Trash.

**Design inventory.** The Design tab's top section, **Observed in this Paper**, counts text styles and colours across *every* Page and says how many Pages each is on, how each Page covers them (the shown Page marked), and, only where the design guide states exact hex colours, which colours in use the guide does not list and which listed colours no layer uses. It is recounted whenever the Paper or its Pages change, never edits or derives `DESIGN.md`, makes no token bindings and calls no model. The curated design guide stays its own section below it, and when it states no hex colours the panel says there is nothing exact to compare.

## Play and motion (preview 28)

**Source of truth.** The editable Paper is authoritative: layers and ids, assets with provenance, layout, authored desktop and mobile artboards, and the optional **preview model**. Play is a runnable preview of that Paper, not code; generated implementation code is a separate handoff and is never called production ready.

**The preview model** (`preview` in `paper.json`, version 1; reference in `skills/paper/references/motion.md`, structure in `preview-model.schema.json`) is data only: numbers in stated ranges, short word lists, hex colours, existing ids and plain text. It holds responsive *variants* (which top-level artboard shows for which window width), local *states* with alternate text, a *pinned* navigation layer, *animations* (timed load and loops, reveal on scroll, scroll-linked, hover, focus and state-driven) and click *interactions* (set a state, go to a Page or artboard, scroll to a layer, go back). Unknown fields, ids that do not exist, out-of-range values and unsupported versions are refused on save, import and create with a sentence; a newer version than 1 still opens and lists but cannot be saved over by this version. Papers without it are unchanged. Deleting a layer or a Page takes its motion with it in the same undo step. It travels in `.paper.zip` and through the same whole-Paper tools a guest or agent already has: no new tool, route or permission.

**No code is run from a Paper.** The native host's content-security policy allows no nested frame, so there is none, and Play does not pretend a shadow root is a sandbox: it is a trusted DOM renderer in the product's own code that interprets validated data with the Web Animations API and ordinary events. A Paper string is only ever shown as text. If a use needs arbitrary embedded code, this version does not provide it.

**Play.** The small ▶ beside the Paper title opens a full-window preview with its own scroll container; the editor's camera, selection, shown Page and open draft are untouched and nothing done in Play is saved. Escape or Back to Edit closes it and returns focus. It builds the variant for the window width (width outside every authored range shows the nearest one, scaled down only to fit, and says so; there is no automatic reflow), pins the navigation layer with real sticky positioning, and offers Play/Pause, Replay, a scrubber in milliseconds (the same time is always the same frame), a Page picker, a viewport choice (Fit window, Desktop 1440, Mobile 390) and one **Reduce motion** control that starts from the system preference: with it, timelines rest on their last frame (a loop on its first) and hover, focus, reveal and state changes are instant. No audio. Nothing runs while idle: Play pauses when hidden or offscreen, its frame loop exists only while a timeline plays, and closing it cancels every animation, listener and observer.

**Live and shared.** Roles can play; only editors author, in the inspector's small **Motion** section (presets, trigger, duration, delay, easing, from/to values, click actions, pin, variants) or through `paper_save`. A new revision rebuilds Play from it, keeping the Page, scroll place, still-valid state and time, and says so. When an invitation ends or expires Play closes at once and cannot be reopened, and its image references are released.

**Static exports** (PNG and JPEG images, the HTML file and the Paper preview page) show the editable layers as they are in Edit: motion is never applied or captured and nothing Play does reaches the Paper. A paused frame cannot be saved from Play in this version, and there is no standalone live-HTML export; the preview model rides inside `.paper.zip`.

## Working together (preview 28)

One practical collaboration method (version 1, `skills/paper/references/collaboration.md`) is carried identically by the Paper, Design, Diagram and Copy skills and served publicly at `/collaboration.md`, so an agent in any host can read it; `scripts/sync-docs.mjs` keeps every copy identical and `npm run check` fails on drift. It covers consultation (no claim of canvas work), pair design, bounded fan-out then one chosen synthesis, sequential takeover and implementation handoff; reading the Paper, `DESIGN.md` and feedback first; agreeing stable layer ids and roles; small revision-checked changes; independent visual review; and, after a 409, re-reading and re-applying one's own change (no blind retry, no automatic merge). `DESIGN.md` is the owner's: an invitation cannot write it or private notes, so a guest proposes a change as feedback and the owner accepts it. A truncated or refused read is reported, never papered over. It uses the host, models and approvals the person already has: no orchestrator, service or model vendor is added.

## Honest limits (preview 28)

Source checks and unit tests are not native GUI qualification. Not claimed here: Finder file clipboard for images (only bitmap clipboard), a save chooser inside a host app (the host's own download is used and only *requested*), Firefox and Safari behaviour of Save As, real Cloudflare Internet qualification of the sharing startup (a controlled fake tunnel stands in), rendered layout of the presence strip and the narrow top bars in every browser, and Play's rendering and input in the native app. Play has no paused-frame export and no standalone live-HTML export.
